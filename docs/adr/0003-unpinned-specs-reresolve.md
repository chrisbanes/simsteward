# Unpinned simulator specs are re-resolved at execution to decide up-to-date

Simsteward picks the newest installed runtime and a suitable device type unless they are pinned, but only pinned values were task inputs, so installing a newer runtime left earlier results up-to-date for a runtime they never ran on. Resolving defaults during configuration would call `simctl` on every configuration, so instead an unpinned task's up-to-date check re-resolves its spec at execution and reruns when the resolved runtime or device type identifier differs from its last run. The cost is one memoised `simctl list -j runtimes` on builds that would otherwise run nothing; pinning both by identifier removes it, while a pin by name is re-resolved like a default. Only identifiers count, matching what the resolved spec holds, so a patch build under the same identifier does not rerun, and a resolution failure counts as out of date so that the lease reports it.
